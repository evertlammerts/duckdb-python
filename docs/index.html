DuckDB for Python

DuckDB is a fast SQL database that runs inside your Python program. There is no server to install or start. It can keep its data in memory or in a file, and it can query CSV, Parquet and JSON files, and pandas, polars and Arrow data, directly. This package, duckdb, is how you use it from Python.

Start here

The examples on these pages show results in comments, the way you see them at the Python prompt or in a notebook. In a script, pass a result to print() to see it. show(con) is different: it prints a table of up to ten rows by itself and returns None.

from duckdb import frame
from duckdb.frame import col, table, count_all

con = frame.connect()
con.run("CREATE TABLE orders (customer VARCHAR, region VARCHAR, total DECIMAL(6,2))")
con.run("INSERT INTO orders VALUES ('acme', 'emea', 1400), ('bolt', 'amer', 320), ('acme', 'emea', 2600)")

orders = table("orders")
orders.filter(col("total") > 1000).rows(con)
# [('acme', 'emea', Decimal('1400.00')), ('acme', 'emea', Decimal('2600.00'))]

Line by line:

  • frame.connect() opens a connection to a new database in memory. It lasts only while your program runs: when the program ends, its tables are gone. To keep them, connect to a file, as in Connecting.
  • con.run(...) runs one SQL statement and returns the number of rows it changed. VARCHAR is text, which Python gets as str; INTEGER and BIGINT are whole numbers, which Python gets as int. DECIMAL(6,2) is an exact number with up to 6 digits, 2 of them after the decimal point. Python gets such values as decimal.Decimal, which keeps those digits exactly, without a float's small errors such as 0.1 + 0.2 giving 0.30000000000000004. A value with more digits after the point is rounded when stored: 1.239 becomes 1.24. to_pandas turns a DECIMAL column into ordinary floats (float64).
  • table("orders") makes a plan: a description of a query that has not run yet.
  • filter(...) adds a condition and gives you a new plan. col("total") > 1000 is an expression: a piece of a query, here "the column total is more than 1000".
  • rows(con) runs the plan on the connection and returns the rows as a list of tuples.

filter did not change orders: it returned a new plan, which we did not keep. orders still means every order. Here it is grouped by region, with each region's total spending and number of orders, largest spending first:

spent = orders.group_by("region").agg(col("total").sum().alias("spent"), count_all().alias("orders"))
spent.sort(col("spent").desc()).show(con)
┌─────────┬───────────────┬────────┐
│ region  │ spent         │ orders │
│ VARCHAR │ DECIMAL(38,2) │ BIGINT │
├─────────┼───────────────┼────────┤
│ emea    │ 4000.00       │ 2      │
│ amer    │ 320.00        │ 1      │
└─────────┴───────────────┴────────┘

This is the same as the SQL SELECT region, sum(total) AS spent, count(*) AS orders FROM orders GROUP BY region ORDER BY spent DESC. alias names a result column, count_all() counts rows, and desc() sorts from large to small. The second line of the table shows each column's SQL type; a sum gets more digits than the column it adds up, so the total has room to grow.

If you prefer to write SQL, sql(...) makes a plan from SQL text, and you run it the same way:

from duckdb.frame import sql

sql("SELECT region, count(*) FROM orders GROUP BY region ORDER BY region").rows(con)
# [('amer', 1), ('emea', 2)]

Nothing runs until a method gets a connection, such as rows(con) or show(con). Because a plan does not belong to a connection, the same plan runs on any database that has a table called orders. Frames & Plans covers all of this.

a file, and a DataFrame

DuckDB reads files and Python data directly. These examples continue from the ones above: they use the same con and the same imports. The DataFrame examples need pandas, which does not come with duckdb: install it first with pip install pandas. This one writes a small CSV file, reads it, filters it and returns a pandas DataFrame:

from duckdb.frame import read_csv

with open("sales.csv", "w") as f:
    f.write("city,amount\nAmsterdam,120\nUtrecht,40\nAmsterdam,75\n")

big = read_csv("sales.csv").filter(col("amount") > 50)
big.to_pandas(con)
#         city  amount
# 0  Amsterdam     120
# 1  Amsterdam      75

And this queries a pandas DataFrame you already have. con.register gives it a name that queries can use as a table. It reads the DataFrame where it is; nothing is copied into the database.

import pandas as pd

people = pd.DataFrame({"name": ["ann", "bob"], "age": [31, 45]})
con.register("people", people)
sql("SELECT name FROM people WHERE age > 40").rows(con)
# [('bob',)]

Installing

pip install -U duckdb

The package needs Python 3.11 or later and nothing else: DuckDB itself is inside it. pandas, polars, pyarrow and numpy are optional; install them if you want to read from them or get results as them. To check which version you have:

import duckdb

duckdb.__version__        # this Python package, for example '0.0.1.dev0'
duckdb.duckdb_version()   # the DuckDB engine inside it, for example 'v2.0.0-alpha46057'

The package and the DuckDB engine have separate version numbers: a new package release may carry a new engine or the same one. When you report a problem, give both.

Two ways to use it

The package has two modules for running queries. They share DuckDB and the error classes, but their connections are different objects. Open a database file once, with frame.connect() or dbapi.connect(); for more frame connections to it, use duplicate(), as in Connecting.

duckdb.frame: the main way

You build queries as plans, from tables, files, SQL text or Python data, and run them on a connection. A frame connection has run(), transaction(), register(), create_function(), create_macro(), duplicate(), interrupt() and close(). It has no execute(), fetchall() or cursors: rows come out of plans. Each statement takes effect at once, unless you group statements in a transaction. Inside with con.transaction(): the statements run as usual, and their changes become final together when the block ends. If an exception leaves the block, all of them are undone. Most DuckDB errors you catch inside the block still spoil the transaction, and then nothing in it is kept; a syntax error (ParserError) does not (see Frames & Plans).

duckdb.dbapi: the standard database interface

Python has a standard interface that database libraries share, called the DB-API (PEP 249). You open a connection, get a cursor from it (the object that runs SQL and hands you its rows), and call execute() and fetchall(). Changes become final when you call commit(); until then, rollback() undoes them. Many tools expect this interface, for example libraries that map Python classes to tables and tools that manage changes to a database's tables. duckdb.dbapi provides it.

from duckdb import dbapi

db = dbapi.connect()
cur = db.cursor()
cur.execute("CREATE TABLE notes (id INTEGER, text VARCHAR)")
cur.execute("INSERT INTO notes VALUES (?, ?)", (1, "hello"))
db.commit()
cur.execute("SELECT text FROM notes WHERE id = ?", (1,))
cur.fetchall()
# [('hello',)]

Which one? Use duckdb.dbapi if you keep SQL strings with ? or $name placeholders, or if a tool needs a DB-API driver. Use duckdb.frame to build queries with Python methods, or to get results as DataFrames. Both suit your own scripts.

A plan does not run on a dbapi connection: that is refused with TypeError. To send a plan's query through a cursor, plan.render_parameterized() gives you its SQL and the values to pass to execute(); DB-API 2.0 has the complete example and its limits.

Connecting

Each line is a separate choice; run one of them:

con = frame.connect()                                     # a new database in memory
con = frame.connect("shop.db")                            # a file, created if it does not exist
con = frame.connect("shop.db", access_mode="read_only")  # a file that must exist, opened read-only
con = frame.connect(threads=2)                            # in memory, with a setting
  • With no path you get a database in memory. It lasts until the last connection to it closes.
  • With a path you get a database file, created if it does not exist yet. A new file starts empty: a table you made in memory earlier is not in it. A read-only connection does not create the file: if it is missing, you get IOError.
  • Keyword arguments are DuckDB settings, applied when the database opens. A setting DuckDB does not know is refused with an error that names it. Some settings, such as access_mode, can only be chosen here; most others can also be changed later with con.run("SET ...").

Open a database file only once in a program, even read-only. A second frame.connect("shop.db") while the first is still open is refused with OperationalError. For another connection to the same database, for example one per thread, use con.duplicate(). A duplicate sees the same tables, not a copy of them, and keeps working after the original is closed.

closing

with frame.connect("visits.db") as visits:
    visits.run("CREATE TABLE IF NOT EXISTS visits (day DATE)")
# the connection is closed here

This example opens a file of its own, so it runs whichever line you chose above. close() closes a connection, and a with block closes it for you at the end. After that, the connection refuses any more work with InterfaceError. Your plans are not affected, since they never belonged to it.

Errors

Every error DuckDB reports is raised as a class from duckdb.exceptions, with DuckDB's own message.

from duckdb import exceptions

con = frame.connect()
try:
    table("nope").rows(con)
except exceptions.CatalogError as error:
    print(error)      # Catalog Error: Table with name nope does not exist!
                      # followed by the place in the SQL

The classes follow the standard Python database hierarchy. Error is at the top, so except exceptions.Error catches every one of them, apart from errors that reach you through another library: reading a to_reader() result raises pyarrow's OSError, and a lazy polars frame raises polars' ComputeError. The ones you will meet most:

ClassWhen
ParserErrorThe SQL has a syntax error.
CatalogErrorA table, view or function you named does not exist, or one you create already does.
ProgrammingErrorThe query does not make sense to DuckDB, for example a column that is not there or a function called with the wrong types. The message starts with Binder Error:. ParserError, CatalogError and InvalidInputError are kinds of ProgrammingError.
InvalidInputErrorAn argument or setting is wrong, for example a setting DuckDB does not know, or two statements in one call.
DataErrorA value is out of range, for example an INTEGER sum that overflows. ConversionError is a kind of DataError.
ConversionErrorA value cannot be converted to the type asked for, such as 'abc'::INTEGER.
ConstraintErrorA primary key, unique, NOT NULL or CHECK rule was broken.
IOErrorA file could not be read or written. This is duckdb.exceptions.IOError, not Python's built-in IOError, so except IOError does not catch it; the same holds for ConnectionError.
OperationalErrorThe database could not do what was asked, for example because a file is already open elsewhere. IOError, OutOfMemoryError and InterruptError are kinds of OperationalError.
InterfaceErrorThe package was used in a way it does not allow, for example a closed connection.
 
con.run("CREATE TABLE orders (customer VARCHAR)")
try:
    sql("SELECT nope FROM orders").rows(con)
except exceptions.ProgrammingError as error:
    print(error)      # Binder Error: Referenced column "nope" not found in FROM clause! ...

Some mistakes are caught in Python before DuckDB sees the query. They raise Python's own TypeError or ValueError: for example a string passed to filter() where an expression is needed, or a plan given a dbapi connection.

Pressing Ctrl‑C while a query runs stops it and raises KeyboardInterrupt, unless the query is calling a Python function of yours: then it fails with InvalidInputError (see Python Functions). From another thread, con.interrupt() stops the query that connection is running; it then fails with InterruptError.
